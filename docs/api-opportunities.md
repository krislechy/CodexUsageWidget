# App-server data opportunities

Reviewed on 2026-10-13 using [official OpenAI app-server documentation](https://learn.chatgpt.com/docs/app-server) and the non-experimental schema output generated by installed `codex-cli 0.154.0` (`codex app-server generate-json-schema`). This is a capability review, not a claim that every metric is populated for the signed-in account. No new account RPCs or model turns were made for this research.

| Data surface | Fields present in the local schema | Reasonable widget addition |
| --- | --- | --- |
| `account/usage/read` | `dailyUsageBuckets` with date/tokens; summary lifetime/peak daily tokens, streaks and longest turn | Optional statistics panel: today's reported usage and a 7/30-day chart. Refresh on opening or infrequently, independently of the second-by-second countdown. |
| `account/rateLimits/read` | Multiple named buckets, credits balance/hasCredits/unlimited, reached-limit classification, plan type; backend usage permission and spend-control metadata | Optional credits balance, extra returned quota buckets and an explicit blocked/available state. Never infer server permission merely from a local countdown reaching zero. |
| `account/read` | Account/auth state and plan type | Account/plan status in Settings, fetched on opening and updated by account notifications. Avoid exposing email on the always-visible widget by default. |
| Earned-reset credit details | Granted/expiry timestamps, nullable title and description | Better reset labels and optional reminders before expiry. Never invent missing records when the backend caps the detail list. |
| `account/workspaceMessages/read` | Feature-enabled flag and timestamped headline messages | Optional workspace notices; useful primarily for team accounts, secondary for a personal quota widget. |
| Thread usage | Token totals, cached input, output/reasoning usage and context window notifications; optional per-thread estimated credits/USD in account usage | Advanced per-chat detail only after selecting a thread. Estimates must be labelled. A separate app-server connection is not guaranteed to stream every other Codex client's active thread. |

Recommended next scope: configurable low-quota/reset-expiry notifications; an on-demand usage statistics panel; credits balance when returned. Threshold notifications reuse already polled quota/reset metadata and require no new endpoint. Keep streaks, longest turns and conversation dashboards out of the default ring view.

Null/absent fields mean unavailable. Account-wide usage statistics do not establish an exact remaining-token allowance. Subscription quota percentages, consumed-token history and purchased-credit balance are separate measures. Daily statistics and estimated cost must not be presented as final billing or as a guaranteed quota conversion.

## Implemented experiment (0.8.0)

The Extra info window now exposes every data surface above, with collapsible sections, reported-field fallbacks, 7/30-day activity, selected-thread estimates, credit/spend metadata and configurable quota/reset-expiry alerts. Reset metadata retains grant time, title and description. The original ring view remains focused on quota. Account usage and workspace capabilities are read-only and account-dependent, as documented in the official source above.

A read-only local smoke check found account, token history and quota data available, 78 reported daily buckets, and a 20-row thread page with a next cursor. Workspace messages were feature-disabled. This is a point-in-time capability result, not a guarantee for other accounts. Live thread context/reasoning metrics stay unavailable until this connection receives an event; the experiment never resumes a conversation to force one.
